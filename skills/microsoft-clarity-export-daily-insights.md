# Export daily Clarity insights

One operation does all of this: `getProjectLiveInsights`
(`GET https://www.clarity.ms/export-data/api/v1/project-live-insights`).

## Before you call anything

**You get ten calls per project per day.** Not ten per hour — ten per day, and
the response carries no header telling you how many are left. Plan the whole
task before the first request, and cache the result.

Check your budget first:

1. Have you already called this API today for this project? If yes, reuse that
   payload — every metric comes back on every call.
2. Can one call answer the whole question? It almost always can, because you
   cannot select metrics: every call returns the full metric set and only the
   dimension slicing changes.

## Authenticate

Send the project token as a bearer credential:

```
Authorization: Bearer <YOUR_API_TOKEN>
Content-Type: application/json
```

The token is a JWT generated by a **project admin** at
Settings -> Data Export -> Generate new API token. If you do not have one, stop
and ask for it — there is no OAuth flow to run and no way to self-issue.

## Build the request

| Parameter | Required | Values |
| --- | --- | --- |
| `numOfDays` | yes | `1`, `2` or `3` — the last 24, 48 or 72 hours |
| `dimension1` | no | Browser, Device, Country/Region, OS, Source, Medium, Campaign, Channel, URL |
| `dimension2` | no | same list |
| `dimension3` | no | same list |

Anything else is a `400`. A fourth dimension is a `400`. `numOfDays=7` is a
`400` — there is no historical export on this API, only the last three days.

```
GET https://www.clarity.ms/export-data/api/v1/project-live-insights?numOfDays=1&dimension1=OS
```

## Read the response

The body is a top-level JSON **array**, not an envelope. Each element is a
metric group:

```json
[
  {
    "metricName": "Traffic",
    "information": [
      { "totalSessionCount": "9554", "totalBotSessionCount": "8369",
        "distantUserCount": "189733", "PagesPerSessionPercentage": 1.0931,
        "OS": "Other" }
    ]
  }
]
```

Three things bite here:

- **Counts are strings, ratios are numbers.** `"totalSessionCount": "9554"` is a
  string. Coerce before you do arithmetic.
- **Row keys vary.** `information[]` rows carry the measure fields for that
  metric plus one key per dimension you requested. Do not assume a fixed shape.
- **Everything is UTC.** Do not re-label it in the user's local timezone.

Filter to the metric you were asked about by `metricName` — Traffic,
Engagement Time, Scroll Depth, Popular Pages, Dead Click Count, Rage Click
Count, Excessive Scroll, Quickback Click, Script Error Count, Error Click Count,
and the dimension-named metrics.

## Handle the failures

| Status | What it means | What to do |
| --- | --- | --- |
| `400` | Bad parameters | Fix `numOfDays` (1-3) or the dimension names. Do not retry blind — you will burn a call. |
| `401` | Missing/invalid/expired token | Ask for a new token. Do not retry. |
| `403` | Token not authorized for this project | A project admin must issue a replacement. Do not retry. |
| `429` | `Exceeded daily limit` | You are out of calls for the day. There is no `Retry-After`. Stop and tell the user when the quota resets. |

**Never retry a 4xx automatically.** Each attempt costs one of ten daily calls,
and a retry loop against a `400` will exhaust the project's entire budget in
seconds.

## Truncation

The response caps at **1,000 rows and cannot be paginated**. If you asked for
three high-cardinality dimensions (say URL x Browser x Country/Region) you are
probably looking at a truncated result and there is no way to fetch the rest.
Say so, and re-slice with fewer or lower-cardinality dimensions on the next
call — if you have a call left.

## What this operation cannot do

- It cannot return session recordings. There is no public REST endpoint for
  those; use the Clarity MCP server's `list-session-recordings` tool or the
  dashboard.
- It cannot go back further than three days.
- It cannot filter — only slice by dimension.
